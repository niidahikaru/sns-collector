# 運用方針の変更と改善メモ

## 前回の運用方針（v1）

### 構成
- 講師が1つのGASをデプロイし、全スクール生がそのURLを共有
- 1つのスプレッドシートに全員のデータが集約される
- スクール生はChrome拡張をインストールし、共通のGAS URLを手動で貼り付け

### 問題点

| # | 問題 | 詳細 |
|---|------|------|
| 1 | **データが全員で共有される** | 他の人の収集データが見えてしまう。プライバシー・権限管理の問題 |
| 2 | **GAS URLのハードコード** | 手順書にURL直書き。変更時に全員へ再配布が必要 |
| 3 | **セットアップ手順が多い** | ZIP展開→拡張インストール→URL手動コピペ。3ステップ目でつまずく人が多い |
| 4 | **スケーラビリティ** | 1つのスプレッドシートに全員分のデータ。シートが肥大化しやすい |
| 5 | **GASの実行クォータ** | 全員が同じGASを叩くため、1アカウントのクォータを共有消費 |
| 6 | **Threads専用** | threads.gs / x.gs が別ファイルで、同じプロジェクトにデプロイすると関数名衝突 |

---

## 今回の改善（v2）

### 方針転換
**「各スクール生が自分のGoogleアカウントでGAS+スプレッドシートを持つ」**

### 改善内容

| # | 改善 | 対応 |
|---|------|------|
| 1 | **データ分離** | 各自のGoogleドライブにスプレッドシートが作成される。自分のデータだけが見える |
| 2 | **URL自動設定** | `setup.mjs` がGASデプロイ→URL取得→`config.json`書き込みまで自動化。手動コピペ不要 |
| 3 | **セットアップ簡略化** | `node setup.mjs` のワンコマンドでGAS作成〜デプロイ完了。あとはChrome拡張を入れるだけ |
| 4 | **スケーラビリティ** | 各自のスプレッドシートなのでデータ肥大化の影響が限定的 |
| 5 | **クォータ分散** | 各自のGoogleアカウントでGASが動くため、クォータを共有しない |
| 6 | **Threads+X統合** | `main.gs` に統合。`platform` フィールドで振り分け。関数名衝突を解消 |

### 具体的な変更ファイル

```
新規:
  setup.mjs              ... clasp でGAS作成→デプロイ→config.json書き込み
  gas/main.gs            ... Threads/X統合版GAS（旧 threads.gs + x.gs を統合）
  gas/appsscript.json    ... GASマニフェスト（webapp設定）
  scripts/make-dist.mjs  ... 配布パッケージ生成
  セットアップ手順書.txt    ... 大幅簡略化（4ステップ→実質2ステップ）

修正:
  src/popup/popup.ts     ... config.json からGAS URL自動読み込み
  package.json           ... npm run dist コマンド追加
```

### GAS統合の技術的ポイント

旧構成では `threads.gs` と `x.gs` がそれぞれ `doPost`, `doGet`, `processData` 等の
同名関数を定義していた。GASはファイル単位のスコープがなくグローバルに展開されるため、
同一プロジェクトにデプロイすると後から読み込まれたファイルで上書きされる。

→ `main.gs` に統合し、`PLATFORM_CONFIG` オブジェクトで設定を切り替える方式に変更。
  拡張側が送る `data.platform`（"threads" | "x"）で振り分け。

## セットアップ体験の比較

### Before（v1）
```
1. ZIPを展開
2. Chrome拡張をインストール（chrome://extensions → デベロッパーモード → フォルダ選択）
3. ポップアップを開いてGAS URLを手動で貼り付け  ← ここでつまずきがち
```

### After（v2）
```
1. ZIPを展開
2. node setup.mjs を実行（Googleログイン → 全自動）
3. Chrome拡張をインストール（GAS URLは自動設定済み）
```
